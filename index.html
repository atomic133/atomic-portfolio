03 DEVELOPMENT & SERVER PHILOSOPHY
01

Async by Default

Never block the main server tick thread. Database queries, disk I/O, Discord webhooks, and HTTP API calls always run on separate worker pools using CompletableFuture or Kotlin coroutines.

RULE: 0ms MAIN THREAD WAIT
02

Packet-Level Interception

Instead of spawning dozens of heavy server-side entities or armor stands, write custom clientbound packet listeners with ProtocolLib. It reduces server memory overhead and keeps client FPS stable.

RULE: MINIMIZE SERVER ENTITY COUNT
03

Clean Gradle Shading

Every library is shaded and relocated via ShadowJar under a custom package prefix. This completely avoids ClassNotFound exceptions or runtime version conflicts with other plugins.

RULE: RELOCATE ALL DEPENDENCIES
04

Fail-Safe Persistence

Player statistics and inventories are flushed using atomic writes and HikariCP connection pools. If the server crashes or force-stops, player progress is preserved without corrupted saves.

RULE: ZERO INVENTORY ROLLBACKS
